# Подготовка существующего кластера команды 12

Эти действия уже были выполнены на учебном кластере. Повторно создавать ключи
или заново устанавливать HDFS не требуется. Для воспроизведения на исходной
среде с работающим HDFS используйте последовательность ниже.

## 1. Пользователь на каждом узле

Выполните от team на каждом из четырёх узлов:

```bash
if ! id hadoop >/dev/null 2>&1; then
  sudo -n adduser --disabled-password --gecos "" hadoop
fi
id hadoop
```

hadoop не добавляется в sudo. В нашей среде ему присвоен UID 1001;
существовавшие файлы установки Hadoop с владельцем 1001 теперь принадлежат
ему. Скрипты используют sudo только для установки конфигов и переключения
с team на сервисного пользователя. В других средах права на установку
могут отличаться; не меняйте рекурсивно владельца каталогов HDFS.

## 2. Ключ для запуска NodeManager

На team-12-nn переключитесь с team:

```bash
sudo -iu hadoop
mkdir -p "$HOME/.ssh"
chmod 700 "$HOME/.ssh"
```

Только если у hadoop ещё нет ключа:

```bash
if [ ! -e "$HOME/.ssh/id_ed25519" ] && [ ! -e "$HOME/.ssh/id_ed25519.pub" ]; then
  ssh-keygen -t ed25519 -N "" -f "$HOME/.ssh/id_ed25519"
fi
cat "$HOME/.ssh/id_ed25519.pub"
```

Приватный ключ остаётся на nn. Скопируйте только выведенную публичную строку.
На каждом рабочем узле (en, 00, 01), от team, задайте переменную hw2_key
с этой строкой и добавьте её пользователю hadoop:

```bash
hw2_key='ВСТАВЬТЕ_ПОЛНУЮ_ПУБЛИЧНУЮ_СТРОКУ_ssh-ed25519'
sudo -n install -d -m 700 -o hadoop -g hadoop /home/hadoop/.ssh
printf '%s\n' "$hw2_key" | sudo -n -u hadoop tee -a /home/hadoop/.ssh/authorized_keys >/dev/null
sudo -n -u hadoop chmod 600 /home/hadoop/.ssh/authorized_keys
```

Не выполняйте блок с незаменённой строкой-заглушкой. Уже добавленный ключ
повторно добавлять не нужно. Файл authorized_keys пользователя team не меняется.

В нашей среде team на nn уже подключался к рабочим узлам и имел их
сохранённые SSH-отпечатки. На nn от team они были скопированы новому пользователю:

```bash
sudo -n install -m 600 -o hadoop -g hadoop \
  "$HOME/.ssh/known_hosts" /home/hadoop/.ssh/known_hosts
```

Используйте этот шаг для нового пользователя с пустым known_hosts.
Если доверенные отпечатки ещё не сохранены, сначала сверьте их с администратором.
Не отключайте проверку SSH-ключей сервера.

Проверка от hadoop на nn:

```bash
for node in team-12-en team-12-00 team-12-01; do
  ssh -n -o BatchMode=yes -o ConnectTimeout=10 "hadoop@$node" 'hostname; whoami' || break
done
```

## 3. Адрес ResourceManager

На nn от team сохраните файл перед редактированием:

```bash
sudo cp -p /etc/hosts "/etc/hosts.bak.$(date +%Y%m%d-%H%M%S)"
sudo nano /etc/hosts
```

Для главного узла должна использоваться строка:

```text
10.12.0.11 team-12-nn.hse.c.mws team-12-nn
```

Конфликтовавшая строка в нашей среде закомментирована:

```text
# 127.0.1.1 team-12-nn.hse.c.mws team-12-nn
```

Остальные записи сохранены. После такого изменения уже работающий YARN
нужно остановить и запустить заново. Не форматируйте и не переустанавливайте HDFS.

## 4. Установка конфигов и запуск

Разместите проект в /home/team/yarn-homework-2 на team-12-en.
Далее используйте раздел «Развёртывание» основного README.
Команда deploy_yarn.sh сама создаёт каталоги логов и резервные копии конфигов.

## 5. Если SecondaryNameNode остался на старом локальном адресе

После изменения /etc/hosts уже запущенный процесс может продолжать слушать
127.0.1.1:9868. Именно это было обнаружено на нашем кластере.
На team-12-nn от team проверьте:

```bash
ss -ltnp 'sport = :9868'
```

Если сервис слушает старый адрес, перезапустите только SecondaryNameNode
от его существующего владельца team:

```bash
/opt/hadoop/bin/hdfs --daemon stop secondarynamenode &&
/opt/hadoop/bin/hdfs --daemon start secondarynamenode
```

Повторная проверка должна показать 10.12.0.11:9868. Перезапуск всех HDFS-сервисов
для этого исправления не выполнялся. После исправления проверка всех девяти
HTTP/JMX-интерфейсов через SSH-туннель завершилась успешно.
